## Usage

```tsx
import {
  Accordion,
  AccordionItem,
  AccordionPanel,
  AccordionTrigger,
} from "@/components/ui/accordion"
```

```tsx
<Accordion defaultValue={["item-1"]}>
  <AccordionItem value="item-1">
    <AccordionTrigger>Is it accessible?</AccordionTrigger>
    <AccordionPanel>
      Yes. It follows the WAI-ARIA accordion pattern.
    </AccordionPanel>
  </AccordionItem>
  <AccordionItem value="item-2">
    <AccordionTrigger>Is it styled?</AccordionTrigger>
    <AccordionPanel>
      Yes, with Tailwind classes you can override through `className`.
    </AccordionPanel>
  </AccordionItem>
</Accordion>
```

## Examples

### Multiple

Allow more than one item to be open at the same time.

```tsx
<Accordion multiple defaultValue={["item-1", "item-2"]}>
  {/* ... */}
</Accordion>
```

### Controlled

```tsx
const [value, setValue] = React.useState<string[]>(["item-1"])

<Accordion value={value} onValueChange={setValue}>
  {/* ... */}
</Accordion>
```

### AccordionTrigger

Renders a `button` inside an `h3` header, with a chevron that rotates when the panel is open. Accepts all `button` props.

### AccordionPanel

The collapsible content area. Height is animated using the `--accordion-panel-height` CSS variable. `AccordionContent` is exported as an alias.

## Migrating from Radix

- `type="single" collapsible` is gone. Single-open is the default, and an open item can always be closed.
- `defaultValue` and `value` are arrays, even in single mode.
- `AccordionContent` is now `AccordionPanel` (the old name still works as an alias).
- The open state is exposed as `data-panel-open` on the trigger, not `data-state="open"`.
